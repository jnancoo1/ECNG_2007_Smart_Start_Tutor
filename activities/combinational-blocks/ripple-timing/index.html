Ripple-Carry Timing and the FPGA Bridge

A sixteen-bit adder is simply sixteen full adders in a line. This activity shows why such a long chain is slow, how the chain is described in hardware code using port mapping, and how the design reaches a Basys 3 board.

Part 1

Watch the carry ripple

Each stage must wait for the carry from the stage before it.

In each column the full adder is in one of three conditions. It generates a carry when A = B = 1, it kills any carry when A = B = 0, and it propagates the incoming carry when A and B differ. Only a propagating stage must wait for its carry in, so a run of propagating stages forms a chain along which the carry travels one stage at a time.

Carry in

Bit 0 is first and the carry travels along the strip, from left to right and then down. Yellow marks a stage whose carry in is still settling, and green marks a stage whose carry out has settled. The model assumes every input changes at the same instant and every stage takes the same delay.

Part 2

Find the slowest input

Set the width to 16, then choose inputs of your own.

With A = FFFF and B = 0001 the carry passes through every stage. Find a different pair of operands (you may also use the carry in) for which the carry still ripples through all sixteen stages. A timing analysis must always assume the worst such input, even though most inputs are far quicker.

Part 3

From chain to hardware

The adder contains no logic of its own. It only connects blocks.

In the hardware description language VHDL each full adder is an entity. The adder is built by creating one copy of the entity per bit and joining the copies with port mapping: each association port => signal pairs a port of the block with a signal of the parent.

signal carry : std_logic_vector(N downto 0);  -- carry(i) is the carry INTO stage i
...
carry(0) <= cin;

stage : for i in 0 to N-1 generate
  fa : entity work.full_adder
    port map (
      a    => a(i),
      b    => b(i),
      cin  => carry(i),
      sum  => sum(i),
      cout => carry(i+1)      -- becomes the next stage's cin
    );
end generate stage;

The key connection

Stage i delivers its carry out on carry(i+1), which is the carry in of stage i+1. This single wire is the ripple, and it is why a longer chain takes longer.

The logic inside full_adder is written as a VHDL function, so each block is purely combinational and can be synthesized. Changing the generic N lengthens the chain. The testbench adds a delay to every stage in simulation, so you can compare the measured settling time with the model in Part 1.

Mapping the design onto the Basys 3

A constraint file (.xdc) tells the tools which physical pin each port uses. Our design uses these board resources:

Port to board mapping
PortBoard resourceRole
sw[15:0]Sixteen slide switchesOperand A
btnL, btnRPush buttonsSelect operand B: 0001, 5555, FFFF or 0000
btnCCentre buttonCarry in
led[15:0]Sixteen LEDsSum
dpDecimal point of the right-hand display digitCarry out (the display is active-low, so the code inverts the signal)

The Tutor does not synthesize designs. To try this on your own computer:

  1. Create a Vivado project and choose the Basys 3 board.
  2. Add the three design files (full_adder.vhd, ripple_adder.vhd and ripple_adder_basys3.vhd) and the constraint file.
  3. Run synthesis and implementation.
  4. Open the timing report and find the delay from a switch to an LED.
  5. Compare it with the worst-case delay from Part 1.
